# VDOO-128 reference-implementation attack reproducer

This source bundle reproduces the public-key-only structural forgery described
in *Practical Public-Key-Only Forgery Against the Submitted VDOO-128
Implementation*.

## Scope

The attack applies to public keys generated by the submitted VDOO-128 reference
implementation. That implementation retains only products involving the
matching oil variable in each oil equation, exposing rank-one derivatives.
The bundle does not claim an attack on the dense vinegar-oil layers defined in
the VDOO specification.

The attack code receives only a public key. A secret key generated by the
reference library is discarded and is never supplied to an attack stage.

## Requirements

- Linux on x86-64 or another platform supported by the included C sources
- GNU Make and a C compiler
- Python 3.10 or later
- NumPy

Extract the archive so that `VDOO_structural_attack` and `ngcc-harness` are
sibling directories.

## Build

```sh
make -C ngcc-harness/sign-33 lib/libvdoo_128.so
make -C VDOO_structural_attack
```

## Reproduce the independently seeded public-key experiment

The included `independent_seeded_public_key.bin` is the public key whose hash
is reported in the paper. No corresponding secret key is included or used.

```sh
python3 VDOO_structural_attack/vdoo_end_to_end.py \
  --pk VDOO_structural_attack/independent_seeded_public_key.bin
```

This performs the full uncached public-key attack. On the machine reported in
the paper (Intel Core i5-6500, single-threaded Python), it took 693.19 seconds.
The last line should report that the submitted verifier accepted the forgery.

## Attack a newly generated submitted-implementation key

```sh
python3 VDOO_structural_attack/vdoo_end_to_end.py --fresh
```

The script writes the resulting public key, message, signature, and verifier
result under `VDOO_structural_attack/forgery_evidence/`. It may also create a
public-only cache named `vdoo128_attack_state.npz` for later runs. Delete or
ignore that cache, or pass `--fresh`, when measuring a full recovery.

The main runner is `vdoo_end_to_end.py`. Its companion modules implement
GF(16) arithmetic, rank-one line recovery, hidden-flag recovery, quotient-map
inversion, and lifting. `vdoo_hash_helper.c` computes the exact verification
target used by the submitted implementation.
